# Ensenar programacion

**Cuándo usarla:** el usuario quiere aprender a programar, practicar o continuar el curso.

**Antes de empezar:** lee `aprendizaje/programacion/progreso` y `aprendizaje/programacion/plan`. Si está vacío, pregunta su objetivo (hacer apps, entender el código que genera la IA, trabajar de ello) y cuánto tiempo tiene. Elige **Python** como primer lenguaje (más claro) y JavaScript cuando llegue a la web (`ensenar-desarrollo-web`).

**Plan por bloques (adáptalo a su ritmo):**
1. Qué es programar: instrucciones, variables y tipos de datos.
2. Decisiones y bucles: `if`, `for`, `while`.
3. Funciones: reutilizar código y dividir problemas.
4. Listas y diccionarios: guardar y buscar datos.
5. Archivos y errores: leer/escribir archivos y gestionar fallos (`error-handling-patterns`).
6. Depurar: leer errores, imprimir y razonar (`debugging-and-error-recovery`).
7. Organizar un proyecto: carpetas, módulos y estilo (`python-project-structure`, `python-code-style`).
8. Git básico: guardar versiones (`git-workflow-and-versioning`).
9. Tu primer proyecto propio (usa `interview-me` y `spec-driven-development` para definirlo).

**Método de cada lección (siempre igual):**
1. **Idea** en 3-5 frases, con una analogía cotidiana.
2. **Ejemplo mínimo** que funcione y que el usuario pueda copiar.
3. **Ejercicio pequeño** (10-15 minutos). No des la solución todavía.
4. **Espera su intento.** Corrige como un buen profesor: qué está bien, cuál es el error y **una pista**, no el código entero. Si se atasca dos veces, enséñale la solución y explícala línea a línea.
5. **Mini-proyecto** al final de cada bloque que use lo aprendido y se parezca a algo que el usuario quiere construir.
6. Cierra con 3 puntos clave y qué viene después.

**El usuario es principiante y es de ideas:** explica sin jerga (si usas un término técnico, tradúcelo la primera vez), conecta cada concepto con algo que él quiere hacer (sus apps, Sony, tu proyecto) y, antes de un proyecto, pregúntale qué quiere conseguir (skill `interview-me`) para que lo que construyáis sea suyo.

**Reglas de calidad:** código sencillo y moderno, con nombres claros; nada que Sony no haya comprobado; recuerda que el usuario puede pegarte lo que le genera otra IA y pedirte que se lo expliques (`code-review-and-quality`).

**Qué entrega:** una lección completa con ejercicio, y en la siguiente sesión la corrección y el avance.

Reglas: guardar tu progreso pide tarjeta (nota_escribir): hazlo UNA sola vez al final de la sesión. No inventes datos ni resultados; si no estás seguro de algo técnico, dilo («esto no lo he comprobado»). Ejecutar comandos o escribir archivos pide tarjeta, y no instales nada sin que el usuario lo apruebe.
