# Revisar código de un proyecto

**Cuándo usarla:** Antes de publicar una versión o tras un cambio grande.

**Pasos:**
1. Leer el cambio (GitHub o carpeta local) en solo lectura.
2. Buscar errores, casos no cubiertos, secretos en el código y problemas de seguridad.
3. Comprobar que hay pruebas y que pasan.
4. Lista de hallazgos ordenada por gravedad, con propuesta de arreglo.

**Qué entrega:** informe de revisión; no hace push ni merge.

Reglas: nada de enviar, publicar, pagar ni manejar contraseñas; todo eso pide tarjeta de permiso al usuario.
